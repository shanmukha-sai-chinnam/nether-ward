1. Overview & Threat Model

Autonomous coding agents (Claude Code, Google Antigravity, OpenCode, Cursor) possess extensive capabilities: executing terminal commands, modifying files, communicating over Model Context Protocol (MCP) sockets, and dispatching multi-turn tool trajectories. However, standard LLM boundaries are porous to indirect prompt injection, stateful drop-and-execute attack sequences, secret leakage, and high-velocity destructive mutations.

Core Principle: Nether Ward enforces deterministic and semantic security boundaries across the entire lifecycle of an AI coding agent: before prompts reach the model (Gateway), during tool execution (MCP Proxy & Sandbox), across directory traversals (Canary Honeypots), and through continuous validation (SAST & Red Team Fuzzing).

The Nether Ward security model categorizes threats across 5 distinct operational layers:

  • L1: Prompt Ingress & Jailbreak Layer: Direct prompt injections, persona overrides, delimiter manipulation, and token-evasion payloads designed to bypass upstream alignment.
  • L2: Tool Invocation & MCP Layer: Hostile tool calls, parameter tampering, command injection (rm -rf /, reverse shells), and multi-turn stateful sequences (stage-then-execute).
  • L3: Execution Boundary & Kernel Layer: Subprocess escapes, privilege escalation, unmanaged network exfiltration, and environment variable poisoning (LD_PRELOAD).
  • L4: Secret Leakage & Data Exfiltration: Reading sensitive host configurations (/etc/shadow, ~/.aws/credentials, .env) and transmitting credentials via outbound network calls.
  • L5: Supply Chain & Codebase Integrity: Dynamic code execution (eval, exec), reflection tricks, base64 stagers, and pickled payload execution embedded inside project repositories.

4. Shannon Entropy Triage & De-Obfuscation

Attackers and indirect prompt injection stagers frequently obfuscate malicious payloads using base64, zlib compression, or character substitution to bypass traditional string matching. Nether Ward analyzes byte distributions using Shannon Information Entropy: 

H(X) = - SUM [ p(x_i) * log2( p(x_i) ) ]   for i = 0 .. 255

Entropy ranges between 0.00 (homogeneous sequence) and 8.00 (uniform random / encrypted data):

  • 0.00 - 3.50: Structured plaintext, source code, JSON, and low-density configuration.
  • 3.50 - 5.80: Standard executable code, compiled scripts, and formatted documentation.
  • 5.80 - 6.80: Base64-encoded blobs, packed data chunks, and hexadecimal strings.
  • 6.80 - 8.00: High-entropy cryptographic ciphertext, compressed payloads, and shellcode stagers.

Sliding Window Formulation: Rather than solely evaluating file-level entropy (which dilutes small stagers inside large files), Nether Ward applies a 64-byte sliding window across the buffer. If any contiguous window exceeds the critical entropy threshold (default: 6.80), the buffer is flagged as an embedded stager.

5. Stdio Model Context Protocol (MCP) Security Proxy Specification

Nether Ward provides a transparent stdio proxy that wraps MCP tool servers. It intercepts line-delimited JSON-RPC 2.0 messages between the client (the AI coding agent) and the server: 

[AI Agent] <--- stdio ---> [Nether Ward MCP Proxy] <--- stdio ---> [Upstream MCP Tool]
Fail-Safe Error Injection: When a hostile tool invocation is detected (e.g. rm -rf /, reverse shell, or tripwire breach), Nether Ward does not crash or kill the subprocess. Instead, it injects a structured JSON-RPC 2.0 error response back to the client:

{"jsonrpc":"2.0","id":1,"error":{"code":-32000,"message":"Nether Ward Sentinel: Tool invocation blocked by policy [NW-SYS-002]"}}

This allows the coding agent session to remain active and recover gracefully without terminating the user's workspace session.

Stateful Multi-Turn Attack Chain Tracking

Individual tool calls may appear benign in isolation but become malicious when executed sequentially. Nether Ward's McpSessionTracker maintains an in-memory state machine across turns:

  1. Drop-and-Execute Sequence: Turn 1 writes an executable script to /tmp/stager.sh. Turn 2 executes bash /tmp/stager.sh. Nether Ward correlates the file write and subsequent execution, blocking Turn 2 with rule NW-MCP-005.
  2. Sensitive Read to Exfiltration: Turn 1 accesses a credential store (/etc/shadow or .env.canary). Turn 2 executes an outbound network command (curl https://...). Nether Ward catches the exfiltration vector and blocks Turn 2 with rule NW-MCP-006.

6. Canary Tokens & Honeypot Tripwires

To detect unauthorized lateral traversal and silent exfiltration, Nether Ward implements synthetic canary token planting: 

nether-ward canary plant --dir <WORKSPACE_DIR>

This command plants synthetic decoy files in the target directory:

  • .aws/credentials: Decoy AWS credentials containing a registered access key (AKIA_CANARY_...).
  • .env.canary: Decoy infrastructure environment file containing an admin database token (nw_canary_key_...).

Verification & Tripwire Trapping: If an agent attempts to inspect, read, or exfiltrate either decoy file, Nether Ward triggers an immediate tripwire breach (rule NW-CAN-002). If the token string appears in any outgoing model prompt or tool parameter, Nether Ward catches the exfiltration vector (rule NW-CAN-001).

7. Operational Velocity Limits & Dual-Key Approval Gates

Runaway autonomous agents can execute high-velocity edits across dozens of files before human intervention is possible. Nether Ward enforces operational velocity bounds:

  • Sliding-Window Token Limiter: Tracks the cumulative rate of characters modified and commands dispatched per minute. If velocity exceeds the configured threshold, execution is throttled with rule NW-VEL-001.
  • Context Quarantine Wrapping: Untrusted external content (web search results, pull request diffs, user-uploaded data) is automatically enclosed in cryptographic boundary markers: 
    <<<CONTEXT_QUARANTINE_BOUNDARY:uuid4>>>
[Untrusted external payload here]
<<<END_CONTEXT_QUARANTINE_BOUNDARY:uuid4>>>
    Any attempt by the agent to interpret instructions inside the quarantine as system instructions is immediately flagged and discarded.
  • Dual-Key Approval Gates: High-risk operations (e.g. database schema drops, raw disk writes, NixOS system rebuild switches) require an explicit secondary authorization key: 
    nether-ward gate auth --token <ADMIN_SESSION_TOKEN> --command "..."

8. Bicameral Semantic Firewall & Gateway

Nether Ward's reverse proxy (nether-ward gateway) listens on port 4000 and exposes an OpenAI-compatible API (/v1/chat/completions). It sits in front of Google Gemini, Anthropic Claude, or local Ollama endpoints.

Bicameral Architecture

Traditional regex firewalls are vulnerable to synonym substitution and semantic evasion. When started with --semantic-firewall, the gateway uses a two-tier evaluation model:

  1. System One (Fast Semantic Discriminator): Powered by TypeSafe Jev System One (evaluate_noul), the gateway evaluates the probability that an incoming prompt contains a policy-violating directive (jailbreak, credential request, unauthorized execution) before forwarding to upstream.
  2. Fail-Open Fallback: If Jev API endpoints are unreachable or unconfigured, the gateway gracefully falls back to deterministic AST and regex security filters, ensuring local operational continuity.

In-Flight Secret Sanitization (--sanitize)

When enabled, all outgoing and incoming payloads are scanned for exposed API keys, private certificates, and tokens. Sensitive values are replaced with deterministic placeholders (e.g. [REDACTED_AWS_KEY]) before persisting in logs or returning to clients.

Adaptive Rate Governor & Token Bucket

Integrated asynchronous token bucket rate limiter with Additive Increase / Multiplicative Decrease (AIMD) quota throttling. Parses upstream Retry-After and X-RateLimit-* HTTP headers on status 429/503 and dynamically applies decorrelated exponential backoff with pseudo-random jitter. Protects upstream quota across concurrent client chat sessions and parallel red team probe workers without manual concurrency tuning.

9. Ephemeral Linux Kernel Namespace Sandbox

Agent-executed shell commands must not operate with full host permissions. Nether Ward's sandbox module enforces hardware-enforced isolation boundaries using native Linux kernel primitives: 

nether-ward sandbox [--no-network] [--workspace <DIR>] -- <COMMAND>
  • PR_SET_NO_NEW_PRIVS: Prevents subprocesses and child binaries from acquiring new privileges via setuid/setgid bits.
  • CLONE_NEWNET Isolation: Unshares the network namespace, providing complete offline execution with zero loopback or external socket access when --no-network is set.
  • Environment Variable Scrubbing: Strips dangerous runtime hooks including LD_PRELOAD, LD_LIBRARY_PATH, PYTHONPATH, and NODE_OPTIONS before executing child processes.
  • Bubblewrap Containerization: If bwrap is detected on the host system, Nether Ward mounts an ephemeral read-only root with a localized tmpfs overlay for the workspace directory.

10. Autonomous Adversarial Red Team Harness

Nether Ward features an asynchronous, multi-worker synthetic red teaming runner that stress-tests AI models against the OWASP Top 10 for Large Language Models.

Assertion Primitives

  • contains / not-contains: Exact substring verification.
  • regex / not-regex: Regular expression pattern assertions.
  • tool-not-called: Verifies that an agent refused to trigger a dangerous tool invocation.
  • sast-clean: Verifies that code generated by the model passes Nether Ward SAST rules with 0 findings.
  • javascript: Dynamic boolean expression evaluation over model response strings.

Autonomous Mutation Fuzzing (--fuzz)

When invoked with --fuzz, Nether Ward dynamically synthesizes mutation variants for every test case in the evaluation suite:

  1. [FUZZ-DELIM]: Wraps prompts inside markdown codeblock escapes and synthetic system boundary tags.
  2. [FUZZ-ROLEPLAY]: Prepends adversarial hypothetical simulation and CTF drill framing.
  3. [FUZZ-POLYGLOT]: Escapes probe payloads into hexadecimal polyglot byte sequences to test string parser normalization.

11. Automated Behavioral Regression (ABR) Guard

Evaluates pull request and commit changes to agent system prompts, policy configurations, and tool schemas before merging. Compares candidate risk scores against baseline security scores to prevent behavioral regressions: 

nether-ward abr --baseline config/redteam_config.yaml --candidate candidate_config.yaml [--max-risk-delta 0.05] [--step-summary summary.md]
  • Bicameral Evaluation: Queries TypeSafe Jev System One (evaluate_score) across calibrated risk levels (Safe, Low, Medium, High) with automated failover to deterministic SAST heuristics.
  • Regression Delta Detection: Flags any commit that increases overall behavioral risk beyond tolerance (default 5%) or introduces high-risk privilege escalations and unmasked credentials.
  • GitHub Actions PR Guard: Emits Markdown audit tables directly to $GITHUB_STEP_SUMMARY on pull request reviews.

13. CLI Reference & Operational Manual

USAGE:
    nether-ward <SUBCOMMAND> [FLAGS] [OPTIONS]

SUBCOMMANDS:
    threat      Static code analysis (SAST), rule listing, and entropy profiling
    mcp         Model Context Protocol security proxy, config audit, and semantic guard
    canary      Plant honeypot decoy files, scan for leaked tokens, and generate tripwires
    velocity    Evaluate agent modification rate limits and context quarantine boundaries
    gate        Enforce dual-key authorization requirements for high-risk operations
    gateway     Start OpenAI-compatible reverse proxy with runtime firewall and sanitization
    sandbox     Execute commands within ephemeral Linux kernel security boundaries
    redteam     Run parallel synthetic red team evaluations against LLM endpoints
    abr         Run Automated Behavioral Regression evaluation comparing prompt risk scores
    inference   Verify local inference engine connectivity (Ollama / vLLM)
    help        Print this message or the help of the given subcommand(s)

Representative Subcommand Invocations

# 1. Run SAST audit with SARIF output
nether-ward threat --sast ./src --sarif ./reports/sast.sarif

# 2. Compute sliding-window entropy across a directory
nether-ward threat --dir ./datasets/threat_samples

# 3. Start transparent MCP proxy with in-flight sanitization and semantic inspection
nether-ward mcp --proxy --sanitize --semantic -- mcp-server-git --repo /path/to/repo

# 4. Plant honeypot canary decoys in workspace
nether-ward canary plant --dir /home/user/workspace

# 5. Scan a directory or payload for canary token leaks
nether-ward canary scan --dir /home/user/workspace
nether-ward canary scan --payload "leaked_token_value_here"

# 6. Start AI security gateway on port 4000 with semantic firewall
nether-ward gateway --port 4000 --sanitize --semantic-firewall

# 7. Execute command inside kernel sandbox without network access
nether-ward sandbox --no-network -- cargo build

# 8. Run synthetic red team evaluation with autonomous mutation fuzzing
nether-ward redteam --dataset datasets/owasp_top10_expanded.jsonl --concurrency 4 --fuzz

# 9. Run Automated Behavioral Regression (ABR) evaluation comparing baseline and candidate
nether-ward abr --baseline config/redteam_config.yaml --candidate config/redteam_config.yaml --max-risk-delta 0.05
